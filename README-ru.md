# pve-crash-with-reboot.sh и pve-crash-no-reboot.sh

Два самодостаточных Bash-скрипта для **санкционированного, деструктивного
тестирования отказоустойчивости** на **одноразовой (disposable) вложенной
(nested) тестовой лаборатории Proxmox VE**.

## Область применения (scope)

- **В область входит:** ВЕСЬ вложенный (nested) тестовый хост PVE, на котором
  запускается скрипт, и ВСЕ гостевые ВМ/контейнеры, работающие внутри него.
  Ожидается их полная недоступность (downtime) во время и после теста.
- **Вне области:** внешний (outer) гипервизор Proxmox, соседние ВМ вне
  тестируемого вложенного хоста, общее хранилище (shared storage) и любые
  резервные копии. Скрипты не предпринимают никаких действий по отношению
  к ним и не должны на них влиять при корректно настроенной вложенности —
  однако сами скрипты **не проверяют и не гарантируют** правильность этой
  изоляции.
- Скрипты **не выполняют** и не предназначены для: удаления/повреждения
  дисков, сетевых атак, отключения watchdog-таймеров, закрепления
  (persistence) в системе или любых иных типов сбоев, кроме паники ядра
  ("kernel panic") текущего хоста.

## Два варианта

| Скрипт | Поведение после паники ядра |
| --- | --- |
| `pve-crash-with-reboot.sh` | Паника ядра, затем **попытка автоматической перезагрузки** через 10 секунд (`kernel.panic=10`). "Резерв" здесь означает именно резервный вариант перезагрузки, а **не** резервную копию данных. |
| `pve-crash-no-reboot.sh` | Паника ядра **без** таймера автоматической перезагрузки (`kernel.panic=0`). Хост потребует ручного вмешательства для восстановления. |

## Требования и защитные проверки

Оба скрипта:

- Написаны на Bash с `set -Eeuo pipefail`, фиксированным
  `PATH=/usr/sbin:/usr/bin:/sbin:/bin` и `LC_ALL=C`.
- Принимают ноль или один аргумент: `--dry-run` (по умолчанию) или
  `--execute`. Любые другие аргументы отклоняются с ошибкой использования.
- Требуют запуска от имени **root** и наличия утилит `pveversion`,
  `systemd-detect-virt`, `hostname`, `sleep`.
- Отклоняют запуск внутри контейнера
  (`systemd-detect-virt --container --quiet`).
- Требуют положительного обнаружения ВМ (`systemd-detect-virt --vm`).
- Проверяют, что `/proc/sysrq-trigger` и `/proc/sys/kernel/panic`
  доступны для записи.

**Важно:** перечисленные выше проверки (root, `systemd-detect-virt`,
доступность файлов `/proc` для записи) **не доказывают**, что текущий
хост действительно является одноразовой вложенной тестовой лабораторией,
и **не являются авторизацией** на выполнение теста. Ответственность за
корректность выбора цели полностью лежит на операторе, запускающем
скрипт.

## Режим `--dry-run` (по умолчанию)

- Ничего не изменяет и не вызывает панику ядра.
- Печатает: имя хоста, обнаруженный тип виртуализации, версию Proxmox VE
  и предупреждения на русском языке о том, что скрипт: аварийно завершает
  ТЕКУЩИЙ хост, прерывает работу вложенных гостевых машин, создаёт риск
  потери данных и **не создаёт резервных копий**.
- Завершается после вывода информации о цели.

## Режим `--execute`

- Требует интерактивного stdin (терминала); при запуске без интерактивного
  ввода завершается с ошибкой.
- Требует точного ввода подтверждающей фразы, включающей текущее имя хоста:
  - `pve-crash-with-reboot.sh`: `CRASH WITH REBOOT <hostname>`
  - `pve-crash-no-reboot.sh`: `CRASH NO REBOOT <hostname>`
- После совпадения подтверждения — пауза 5 секунд, затем запись в
  `/proc/sys/kernel/panic` (10 секунд для варианта с перезагрузкой, 0 для
  варианта без перезагрузки) и вызов паники ядра через
  `echo c > /proc/sysrq-trigger`.

## Пример использования

```bash
# Просмотр цели воздействия без каких-либо изменений (безопасно):
./pve-crash-no-reboot.sh
./pve-crash-no-reboot.sh --dry-run

# Реальный запуск теста (ТОЛЬКО на одноразовой вложенной лаборатории!):
sudo ./pve-crash-with-reboot.sh --execute
```
