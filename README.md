# Тесты паники Proxmox VE

Скрипты `pve-crash-with-reboot.sh` и `pve-crash-no-reboot.sh` предназначены
для авторизованного тестирования сбоя **внутри одноразовой вложенной VM
Proxmox VE** и её внутренних VM/CT. Внешний гипервизор, соседние машины,
общее хранилище и резервные копии не входят в область теста. Это тест паники
ядра, а не исчерпывающая проверка отказов отдельных компонентов.

## Проверка

По умолчанию выполняется безопасный сухой прогон:

```bash
sudo ./pve-crash-with-reboot.sh
sudo ./pve-crash-no-reboot.sh --dry-run
```

Сухой прогон ничего не записывает в `/proc` и не вызывает сбой. Перед
`--execute` проверьте через консоль **внешнего гипервизора**, что обнаруженная
VM действительно является нужной вложенной VM: автоматическое обнаружение VM
этого не доказывает.

## Запуск

Оба скрипта требуют root, systemd и доступные для записи
`/proc/sysrq-trigger` и `/proc/sys/kernel/panic`. Контейнеры отклоняются.

```bash
sudo ./pve-crash-with-reboot.sh --execute
sudo ./pve-crash-no-reboot.sh --execute
```

`pve-crash-with-reboot.sh` устанавливает `panic=10`: после паники узел
перезагрузится автоматически примерно через 10 секунд. «С резервом» означает
только этот таймер автоматической перезагрузки, а не создание резервной копии.
`pve-crash-no-reboot.sh` устанавливает `panic=0`; автоматическая
перезагрузка не выполняется, поэтому восстановление может потребовать
внешней консоли или сброса VM.

В режиме выполнения каждый скрипт требует интерактивный stdin и точную фразу
подтверждения, показанную на экране. После подтверждения запись `c` в
`/proc/sysrq-trigger` преднамеренно вызывает панику ядра. Не запускайте эти
скрипты на рабочем или не одноразовом узле.
